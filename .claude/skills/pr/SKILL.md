# PR の作成からマージまでの手順

## 1. 準備ができているか確認する

1. `git status` で、今いるのが作業ブランチ（`main` ではない）であること、コミットしていない変更がないことを確認する。
   - コミットしていない変更があったら、先に `/commit` を使うよう私に伝えて止める。
2. 作業ブランチが GitHub にプッシュ済みかを確認する。まだなら `git push -u origin <ブランチ名>` を実行する。
3. `gh pr list --head <ブランチ名>` で、同じブランチの PR がすでにないかを確認する。

## 2. PR のタイトルと説明文を作る

- **タイトル**：コミットメッセージと同じ形式 `種類: 内容`（種類は commit スキルの表に合わせる）。
- **説明文**：次の4つの見出しで書く。読む人（選考担当者・未来の自分）が、何をなぜ変えたのかをすぐ分かるようにする。

```markdown
## 概要
何を作ったか・なぜ作ったかを1〜2文で書く。

## 変更内容
- 変えたファイルごとに、何をしたかを箇条書きで書く

## 動作確認
1. 確認した手順を番号付きで書く
2. 何が起きれば OK かを書く

## 次にやること
- この PR のあとに予定している作業を書く（なければ「なし」）

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

- 動作確認は、私が実際に確認したことだけを書く。確認していないことは書かない。

## 3. 私の確認を取ってから PR を作る

1. タイトルと説明文を私に見せ、「これで PR を作ってよいか」を聞く。
2. 了承されたら `gh pr create --base main --head <ブランチ名> --title "<タイトル>" --body-file -` で作成する。
3. できた PR の URL を私に伝える。

## 4. マージする

1. 「GitHub の画面で自分でマージするか、`gh pr merge` でマージするか」を私に聞く。
   - 自分でマージする場合：**Merge pull request** → **Confirm merge** の順に押すよう伝え、終わるのを待つ。
   - 任された場合：`gh pr merge <番号> --merge` を実行する。
2. `gh pr view <番号> --json state` で、`MERGED` になったことを確認する。

## 5. 後片付け（ブランチを消して main を最新にする）

1. コミットしていない変更があれば、`git stash` で一時的に避難させる。
2. `git switch main` で main に移る。
3. `git pull` で、マージ後の最新の状態を取ってくる。
4. `git branch -d <ブランチ名>` で、手元の作業ブランチを消す。
5. `git push origin --delete <ブランチ名>` で、GitHub の作業ブランチを消す（画面の **Delete branch** で消してあれば不要）。
6. `git fetch --prune` で、消したブランチの情報を手元からも片付ける。
7. 1 で避難させた変更があれば、`git stash pop` で戻す。
8. `git log --oneline -3` を見せて、main にマージが入ったことを私と確認する。
